Vitrine UI

A white-label chat widget where the model picks components instead of writing prose — and never writes markup.

Eight typed components in a registry. The model calls one by name and fills a JSON payload; anything that fails schema validation is dropped before it reaches the DOM. Swap src/registry.js and the whole thing retargets at a different industry. No build step, no dependencies, no framework.

Tenant theme

Four tokens are writable: accent, radius, typeface, logo. Layout, spacing, depth and motion stay host-owned — that split is what keeps fifty brands on one codebase.

Contrast gate

Every accent is measured before it is applied. Try Citrus — a real brand yellow that fails WCAG AA out of the box — and watch the gate correct it rather than ship an unreadable widget.

    On the wire

    Exactly what the planner emitted for the last turn. This is the entire contract: a component name and a payload. No HTML, no JSX, no CSS.

    Run it against a real model

    The demo ships with a deterministic offline planner so it works with no key. Paste an Anthropic key to bind the same registry schemas as tools and let a live model choose the components.

    The key never leaves your browser, but a browser-side key is a demo affordance, not a deployment. In production the planner call belongs behind your own endpoint — see Going live in the README.

    Deterministic planner · no network

    Built as a reference implementation of the registry pattern — the same model behind Google's A2UI and MCP Apps: the agent composes from a catalog the client already trusts, so a hallucination costs you one dropped card rather than an injection. MIT licensed.
